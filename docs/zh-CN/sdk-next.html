下一版 SDK 设计 ​

本文定义下一版 VILab SDK 的职责边界和 API 方向，用于配合 WebSocket 实时语音协议落地。它描述的是下一版目标，不等同于当前已经发布或当前仓库中的 HTTP SDK 能力。

核心结论 ​

下一版 SDK 只做一件事：作为 VILab 实时语音服务的客户端。

SDK 负责：

  • 连接 VILab WebSocket 实时语音接口。
  • 发送 session.start。
  • 按 pcm_s16le / 16000Hz / mono 发送 binary audio frame。
  • 发送 audio.end 或 session.cancel。
  • 接收 ASR 和 LLM 事件。
  • 把服务端事件转换为开发者容易消费的类型。

SDK 不负责：

  • 管理 ASR 或 LLM Provider。
  • 管理 Provider API Key。
  • 添加、删除、修改或切换模型。
  • 选择 pipeline。
  • 调用 Admin API。
  • SDK 直连 LLM。
  • 本地 ASR 或本地 LLM runtime。
  • 桌面端文本插入、剪贴板、输入法桥接。

服务端是模型、Provider、Prompt 和 routing 的配置中心。SDK 是普通调用方，不是管理端。

与当前 SDK 的区别 ​

当前 TypeScript / Python SDK 主要围绕 HTTP Public API：

  • POST /v1/audio/transcriptions
  • POST /v1/pipeline/runs
  • POST /v1/pipeline/runs/stream

其中 stream() 是上传完整音频后的 NDJSON 阶段事件流，不是真正的麦克风实时 WebSocket 流。

下一版 SDK 会以 WebSocket 为主：

  • 使用 /v1/realtime/sessions。
  • 音频边录边发。
  • 事件边处理边返回。
  • 不暴露 raw、smart_clean、polish 等 pipeline 参数。
  • 不再扩展 SDK-local LLM config、models.add/update/delete/use、mode.set(local/remote) 等能力。

旧 HTTP SDK 可以在迁移期保留，但它不是下一版 SDK 的主要方向。

支持平台 ​

V1 先定义两个 SDK 方向：

SDK运行环境职责
TypeScript SDKBrowser、Node.js连接 WebSocket，发送 PCM 音频，消费事件。
Python SDKPython 服务端、脚本、测试工具连接 WebSocket，发送 PCM 音频，消费事件。

平台差异：

  • Browser 不能直接在 WebSocket 握手中设置自定义 Authorization header，因此使用短期 query token。
  • Node.js 和 Python 可以使用 Authorization: Bearer <token>。
  • Browser 可以提供麦克风采集辅助工具。
  • Node.js 和 Python V1 优先接收开发者传入的 PCM 音频流；是否内置跨平台麦克风采集工具可以后续再定。

鉴权 ​

SDK 只负责把 token 放到协议要求的位置。

内测阶段服务端只校验鉴权字段是否存在，不校验 token 内容。SDK API 仍应保留 token 字段，方便后续无破坏升级到真实鉴权。

TypeScript Node.js / Python：

text
Authorization: Bearer <token>

Browser：

text
/v1/realtime/sessions?token=<token>

token 来源由业务系统决定。VILab SDK 不负责登录、账号体系、token 续期或权限管理。

音频输入 ​

SDK 对服务端发送的音频必须是：

json
{
  "encoding": "pcm_s16le",
  "sampleRate": 16000,
  "channels": 1
}

V1 SDK 应提供两层能力：

  1. 核心层：接收 AsyncIterable<Uint8Array> 或等价的 PCM byte stream，直接发送 binary audio frame。
  2. 辅助层：在 Browser 中把 MediaStream 转成 16kHz、mono、pcm_s16le，再交给核心层发送。

核心层是必须能力，辅助层可以按平台逐步补齐。

SDK 不应把每个音频块包成 WAV。WAV 只适合旧 HTTP 整段上传路径；实时 WebSocket 使用 binary PCM frame。

推荐发送策略：

  • 每 100ms 发送一个 binary audio frame。
  • 单帧不超过 32000 bytes。
  • 单次会话最大音频时长 5 分钟。

TypeScript API 草案 ​

Browser ​

ts
import { VILabRealtimeClient } from '@vilab/client/realtime';

const client = new VILabRealtimeClient({
  serverUrl: 'https://vilab.example.com',
  token: realtimeToken,
  auth: 'query',
});

const mediaStream = await navigator.mediaDevices.getUserMedia({ audio: true });

const session = client.createSession({
  language: 'zh-CN',
  textContext: {
    beforeCursor: '',
    selectedText: '',
    afterCursor: '',
    markedText: '',
  },
});

for await (const event of session.streamMicrophone(mediaStream)) {
  if (event.type === 'asr.final') {
    console.log('ASR:', event.text);
  }
  if (event.type === 'llm.delta') {
    renderPreview(event.text);
  }
  if (event.type === 'session.completed') {
    renderFinal(event.finalText);
  }
}

Node.js ​

ts
import { VILabRealtimeClient } from '@vilab/client/realtime';
import { createPcm16StreamFromMic } from './audio';

const client = new VILabRealtimeClient({
  serverUrl: 'https://vilab.example.com',
  token: process.env.VILAB_REALTIME_TOKEN!,
  auth: 'header',
});

const pcm = createPcm16StreamFromMic({
  sampleRate: 16000,
  channels: 1,
});

const session = client.createSession({ language: 'zh-CN' });

for await (const event of session.streamPcm(pcm)) {
  console.log(event.type, event);
}

分步控制 ​

需要更细控制时，SDK 可以提供显式 session 生命周期：

ts
const session = client.createSession({ language: 'zh-CN' });

await session.start();

for await (const chunk of pcmChunks) {
  await session.sendAudio(chunk);
}

await session.end();

for await (const event of session.events()) {
  console.log(event.type);
}

Python API 草案 ​

python
from vilab_client.realtime import VILabRealtimeClient
from my_audio import pcm16_microphone_stream

client = VILabRealtimeClient(
    server_url="https://vilab.example.com",
    token="dev-token",
)

session = client.create_session(language="zh-CN")

for event in session.stream_pcm(pcm16_microphone_stream()):
    if event.type == "asr.final":
        print("ASR:", event.text)
    elif event.type == "llm.delta":
        print("Preview:", event.text)
    elif event.type == "session.completed":
        print("Final:", event.final_text)

异步版本：

python
async with client.create_session(language="zh-CN") as session:
    async for event in session.stream_pcm_async(pcm16_stream()):
        print(event.type)

Python SDK V1 可以先要求调用方传入已经标准化的 PCM stream。跨平台麦克风采集可以作为示例或后续辅助包，不作为核心协议客户端的前置条件。

事件类型 ​

SDK 应直接映射 WebSocket 协议事件：

  • session.started
  • asr.partial
  • asr.final
  • llm.delta
  • llm.final
  • session.completed
  • session.cancelled
  • error
  • config.updated，可选

SDK 可以提供类型封装，但不应重命名服务端事件，避免协议和 SDK 文档脱节。

示例 TypeScript 类型：

ts
type RealtimeEvent =
  | { type: 'session.started'; sessionId: string; configVersion?: string }
  | { type: 'asr.partial'; sessionId: string; text: string; stability?: number; elapsedMs?: number }
  | { type: 'asr.final'; sessionId: string; text: string; elapsedMs?: number }
  | { type: 'llm.delta'; sessionId: string; delta: string; text: string; elapsedMs?: number; timeToFirstTokenMs?: number }
  | { type: 'llm.final'; sessionId: string; text: string; elapsedMs?: number; timeToFirstTokenMs?: number }
  | { type: 'session.completed'; sessionId: string; rawText: string; finalText: string; timings?: RealtimeTimings }
  | { type: 'session.cancelled'; sessionId: string; reason?: string }
  | { type: 'error'; sessionId?: string; code: string; message: string; stage?: string; fatal: boolean };

错误处理 ​

SDK 应遵守协议错误语义：

  • 收到 error.fatal=true 后，应抛出或返回 fatal error，并等待连接关闭。
  • SDK 应优先暴露最后一个 error 事件，不只暴露 WebSocket close reason。
  • 如果连接异常关闭且没有 error 事件，SDK 应返回 connection_closed 类错误。
  • 如果调用方在 session.started 前发送音频，SDK 应在客户端侧直接拒绝，避免把协议错误发给服务端。

常见 SDK 错误：

  • missing_token
  • connection_failed
  • invalid_audio_chunk
  • audio_duration_exceeded
  • server_error
  • connection_closed

配置热更新 ​

SDK 不管理服务端配置。

Web 管理端修改 ASR、LLM、Prompt 或 routing 后：

  • 新建 SDK 会话使用最新服务端配置。
  • 已经开始的 SDK 会话继续使用 session.start 时刻的配置快照。
  • SDK 可以读取 session.started.configVersion 和 session.completed.configVersion 用于日志或诊断。
  • config.updated 是可选事件。SDK 可以透传，但不能依赖它。

与桌面端和输入法的关系 ​

SDK 不做桌面能力。

桌面端负责：

  • 麦克风设备选择。
  • 系统快捷键。
  • 录音 UI。
  • 文本插入。
  • 剪贴板。
  • 输入法桥接。

输入法端继续使用桌面客户端内嵌本地服务的 /admin/ime/*。SDK 不替换输入法 bridge。

如果 SDK 连接的是桌面端暴露的本机服务地址，它仍然只消费该服务的 WebSocket 实时语音能力，不管理桌面端本地模型或 Provider。

迁移策略 ​

迁移期可以同时保留旧 HTTP SDK 和新实时 SDK。

建议分阶段：

  1. 新增 realtime 命名空间，不破坏当前 VILab / VILabClient HTTP API。
  2. 文档把新集成推荐入口切到 VILabRealtimeClient。
  3. 将旧 stream() 明确标注为“上传完整音频后的 NDJSON 阶段事件流”，不是实时麦克风流。
  4. 后续大版本再考虑移除 pipeline、SDK-local LLM config 等旧能力。

实现优先级 ​

第一阶段必须实现：

  • WebSocket 连接。
  • 握手鉴权字段传递。
  • session.start。
  • PCM binary frame 发送。
  • audio.end。
  • 服务端事件解析。
  • fatal error 处理。
  • TypeScript Node.js 核心层。
  • Python 核心层。

第二阶段实现：

  • Browser MediaStream 到 PCM 的辅助转换。
  • TypeScript 浏览器端短期 query token 接入。
  • 更完整的重连和取消处理。
  • 协议兼容测试。

第三阶段再考虑：

  • Python 麦克风采集示例。
  • Node.js 麦克风采集示例。
  • 更细的音频质量诊断。
  • config.updated 事件透传。

与协议文档的关系 ​

SDK 必须以 WebSocket 实时语音协议 为准。

如果 SDK API 草案和协议文档冲突，以协议文档为准；SDK 文档需要同步修正。
