ASR Harness ​

ASR Harness 用来把一组固定音频语料重复发送到正在运行的 VILab HTTP 服务，并输出可比较的转录质量、耗时和错误分类。它只覆盖 provider 级语音转录验证，不负责启动桌面端、录音、文本插入或 Windows IME。

准备语料 ​

语料使用 JSONL，每行一个用例。真实语音、参考文本和运行结果都可能包含敏感信息，应放在已忽略的 artifacts/evals/asr-corpus/ 或本机私有目录。默认输出目录 artifacts/evals/asr-harness/ 也已加入 .gitignore。

jsonl
{"id":"case-001","audioPath":"recordings/case-001.wav","referenceText":"hello world","language":"en","source":"local-golden","scene":"notes","tags":["golden"]}

字段说明：

  • id：必填，用例 ID。
  • audioPath：必填，音频路径；相对路径按 corpus 文件所在目录解析。也兼容 Typeless replay queue 的 audioPackagePath。
  • referenceText：可选，人工参考文本；提供后会计算 CER/WER。
  • language：可选，覆盖命令行 --language。
  • source、scene、tags：可选，用于分组和后续分析。
  • audioSha256：可选；提供后 harness 会校验音频内容，避免语料被意外替换。

运行 ​

先启动 VILab 服务，并准备 /v1/audio/transcriptions 可用的 external API key。建议通过环境变量传 key，不要把 key 写在命令行参数里。

powershell
$env:VILAB_REPLAY_API_KEY = "..."
python scripts/eval-asr-harness.py `
  --corpus artifacts/evals/asr-corpus/corpus.jsonl `
  --server-url http://127.0.0.1:9876 `
  --model vilab-stt-default `
  --language auto `
  --max-cer 0.08 `
  --max-wer 0.18

也可以通过 npm script 启动。当前 Windows/npm 组合需要额外的参数分隔符，确保 --corpus 原样传给 Python：

powershell
npm run asr:harness -- -- --corpus artifacts/evals/asr-corpus/corpus.jsonl

默认情况下，质量阈值失败只会写入结果，不会让命令失败。需要把阈值失败作为 CI gate 时再加：

powershell
python scripts/eval-asr-harness.py --corpus artifacts/evals/asr-corpus/corpus.jsonl --fail-on-threshold

如果结果包含敏感文本，使用 --redact-text。该模式会清空输出里的 referenceText、transcript 和 rawTranscript，只保留 sha256、指标和错误分类。

输出 ​

默认输出目录为 artifacts/evals/asr-harness/asr-harness-<timestamp>/，也可以用 --out-dir 指定。

  • manifest.json：运行参数摘要，不包含 API key。
  • asr-results.jsonl：逐条结果，包含 transcript 或 redacted 状态、音频 sha256、耗时、CER/WER、quality flags、错误分类和 passed。
  • asr-results.csv：便于表格查看的结果。
  • asr-report.json：汇总指标和完整结果。

结果会同时保留 ASR harness 字段和 Typeless replay 风格字段。例如 transcript 与 rawTranscript 都表示本次 ASR 输出，requestMs、transcriptionMs、totalMs 在 ASR-only 阶段一致，sttProviderId 固定为 vilab_http，sttModel 来自 --model。

运行错误会让命令非零退出，例如缺 API key、音频不存在、HTTP 失败、响应不是 JSON 或 transcript 为空。quality_threshold_failed 默认只计入质量失败；只有设置 --fail-on-threshold 才会非零退出。

与 Typeless Replay 的关系 ​

Typeless replay 仍用于从 Typeless 数据集回放 VILab 的完整转录和后处理链路。ASR Harness 更窄，只验证固定音频到 /v1/audio/transcriptions 的 provider 级表现，适合做模型、服务和参数的横向对比。
