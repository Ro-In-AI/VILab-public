术语表 ​

Admin Key ​

Admin Key 只用于 /admin/* 管理接口，例如 Provider 配置、Routing、模型管理和 external API key 管理。它属于宿主机管理员、部署脚本或受控运维环境，不应该写入普通客户端、SDK、Web 前端或第三方集成。

常见来源：

  • VILAB_ADMIN_KEY 环境变量
  • 首次启动生成的 initial-admin-key.json
  • 容器内 vilab init 自动读取的初始管理凭据

external API key ​

external API key 是普通客户端、SDK 和业务集成调用 Public API 的凭据，用于 /v1/models 和 /v1/audio/transcriptions。它可以按项目、设备或环境单独创建和吊销。

常见来源：

  • 首次启动生成的 initial-api-key.json
  • vilab keys initial
  • vilab keys create --name "<client-name>"
  • 桌面设置页的 External API keys

Provider API Key ​

Provider API Key 是第三方语音或大模型服务的密钥，例如 Groq、OpenAI 或后续其它 Provider 的 key。它只保存在服务端，用来让 VILab Server 代表客户端调用上游 Provider。

Provider API Key 不等于 VILab external API key，也不应该分发给客户端。

Public API ​

Public API 是客户端和 SDK 调用的公开能力接口，当前包括：

  • GET /v1/models
  • POST /v1/audio/transcriptions

Public API 使用 external API key 鉴权，不接受 Admin Key 作为客户端 token。

Admin API ​

Admin API 是服务端管理接口，路径统一位于 /admin/*。它使用 Admin Key 鉴权，面向管理员、CLI 和部署脚本，不面向普通客户端。

远程 VILab Server ​

远程 VILab Server 是部署在云服务器、工作站或局域网宿主机上的统一语音服务。普通客户端默认连接远程 Server，并只保存 Server URL、external API key 和公开模型名。

本机内嵌服务 ​

本机内嵌服务是桌面 App 内部启动的 VILab Server，主要用于单机离线、开发调试或局域网宿主场景。即使连接本机内嵌服务，普通调用方也应该使用 external API key；Admin Key 仍只留在管理侧。

核心 prompt ​

核心 prompt 是 polished 后处理里长期稳定的编辑契约，例如只输出最终文本、不要回答口述里的请求、保留高风险 token、上下文不明确时不要猜专名。它不承担完整词库职责，也不应该持续堆叠具体热词示例。

热词上下文 ​

热词上下文是在单次 polished 请求中按需追加的候选纠错信息。它来自用户词库或内置热词 profile，只有当前输入文本命中相关语境时才会注入，例如把 TTT 作为 TDD 的候选、把某个错听项目名修回标准写法。

热词上下文不是强制替换规则。Provider 仍需要结合当前句意判断；上下文不明确时应保留输入原词。详见 热词上下文。

内置热词 profile ​

内置热词 profile 是 VILab 自带的一组常见 ASR 错听候选，主要覆盖开发、prompt 评估、语音转录、项目名等高频场景。它以数据形式维护在代码中，并通过测试保证“相关时注入、不相关时不注入”。后续可以继续迁移为可配置的用户或团队词库。
