API Key 指南 ​

两类不同的 VILab Key ​

Admin Key ​

Admin Key 只用于 /admin/* 管理接口，包括：

  • /admin/status
  • /admin/providers
  • /admin/routing
  • /admin/api-keys

Admin Key 属于宿主机管理员，不应该发给普通客户端、SDK、Web 前端或第三方集成。

external API key ​

external API key 用于 Public API，是普通客户端、SDK 和业务集成的标准凭据：

  • /v1/models
  • /v1/audio/transcriptions

不要把 Admin Key 填进 SDK 的 apiKey 或桌面客户端的 API Key 输入框；这些位置都应该使用 external API key。

vilab transcribe <file.wav> 调用的也是 /v1/audio/transcriptions，因此必须显式传入 --api-key <external-api-key>。即使环境里配置了 VILAB_ADMIN_KEY，CLI 也不会把 Admin Key 当作 Public API token 使用。

无头服务端首次启动时，如果还没有 external API key，会自动创建一把名为 default 的初始 key。完整值会写入服务端数据目录的 initial-api-key.json，也可以由管理员通过 vilab keys initial 查询。

普通列表接口和 vilab keys list 只展示 preview，不长期展示所有 key 的完整值。如果忘记某个完整 key，推荐创建新 key 后替换客户端配置。

推荐签发策略 ​

  • 一把 key 对应一个项目或设备
  • 不建议长期整团队共用一把 key
  • 某个 key 泄露时可以独立吊销，不影响其他调用方
  • 用量可以按集成来源而不是按个人来区分

创建与吊销流程 ​

  1. 打开 设置 → External API keys
  2. 以项目粒度创建新 key
  3. 立即复制完整值
  4. 只把它分发给对应的集成方
  5. 集成下线或泄露时直接吊销

命名示例 ​

  • web-dashboard-prod
  • web-dashboard-staging
  • python-batch-reports
  • warehouse-mic-gateway-02

标准请求头 ​

http
Authorization: Bearer vilab_xxxxxxxxxxxxxxxxxxxx

当前暂不包含 ​

这一阶段没有实现：

  • Key scope
  • 过期时间
  • 单 key 限流
  • 团队级权限控制
