发布环境迁移指南（mac 机器切换） ​

本页用于记录 macOS 发布环境在不同机器之间迁移的标准流程，重点对应 scripts/migrate-release-env.sh（yarn release:migrate）。

一句话流程 ​

  • 迁出（备份）：yarn release:migrate
  • 迁入（恢复）：yarn release:migrate --input <备份文件> --decrypt
  • 迁出后建议加密：带上 --encrypt
  • 不确定走哪一步时：加 --ask 让脚本提示你选择

备份（从旧机器导出） ​

bash
yarn release:migrate --name orulink-2026-05 --encrypt

会自动打包以下内容到主目录下（默认文件名为 ~/release-<时间>.tar.gz，加密时为 .enc）：

  • ~/.tauri/vilab-updater.key
  • ~/.tauri/vilab-updater.key.pub
  • ~/.tauri/vilab-updater.password
  • ~/orulink-secrets
  • ~/.orulink-build-secrets
  • .vilab-release-env.sh（仅环境变量模板，默认不写明文）

说明 ​

  • --include-env：把当前 shell 中发布相关环境变量写入备份中的 .vilab-release-env.sh（默认关闭，避免明文泄露）。若开启会强制加密。
  • MIGRATE_SECRET_PASSPHRASE：如设置，会自动复用为备份加密口令。

恢复（在新机器导入） ​

bash
yarn release:migrate --input ~/Downloads/release-xxxx.tar.gz.enc --decrypt --import-certificate

恢复后会执行：

  • 拷贝文件到目标目录
  • 修正关键文件权限（600/700）
  • 如果本地具备 updater 私钥与公钥，会尝试跑一遍 node scripts/verify-updater-signing-key.mjs
  • 可选导入开发者证书到 login keychain（配合 --import-certificate）

后续你需要手工核对 ​

bash
node scripts/verify-updater-signing-key.mjs
security find-identity -v -p codesigning "$HOME/Library/Keychains/login.keychain-db" | grep -i "Developer ID Application"

自动识别规则 ​

migrate-release-env.sh 会按以下规则判断方向：

  • 有 --input 参数 ⇒ 自动走“迁入（restore）”
  • 其他情况 ⇒ 默认走“迁出（backup）”
  • 加 --ask 可在未显式指定时在终端询问你是“迁入”还是“迁出”

脚本参数（可按需选） ​

  • backup（默认）
  • restore
  • --output <file>：自定义备份文件路径
  • --input <file>：恢复文件路径
  • --encrypt：备份加密（建议）
  • --decrypt：恢复时解密
  • --include-env：把发布环境变量写入模板并加密备份（默认关闭）
  • --import-certificate：恢复后将 .p12 导入钥匙串
  • --ask：运行前让脚本确认迁移方向

常见误区 ​

  • 只复制脚本是不够的：核心是密钥和证书文件本身，必须一起迁移。
  • 不要把敏感明文口令记到公开记录里；建议每次迁移时使用 --encrypt。
  • 恢复后仍需按机器实际环境补充 ~/.vilab-release-env.sh 中的 placeholder（如 APPLE_PASSWORD 等）。
