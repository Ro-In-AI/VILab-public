Typeless 数据集采集与意图传达评估体系 ​

背景 ​

VILab 的听写后处理目标不是简单清理 ASR 文本，而是把用户口述里的真实意图稳定、准确、自然地传达出去。Typeless 的本地历史数据正好覆盖真实口述、应用上下文、音频文件和 Typeless 处理后的文本，因此适合作为第一批“人类意图传达”数据来源。

这里需要明确一个边界：Typeless 的 refined_text 应被视为强 teacher/reference output，而不是绝对 gold label。最终 gold 仍应来自人工复核后的脱敏 golden cases。音频 .ogg 是最重要的原始载体，后续可以用它重放 VILab 的 ASR、smart clean 和 polished 链路。

数据导出脚本 ​

主脚本：

bash
python scripts/export-typeless-dataset.py

Windows 便捷入口：

powershell
powershell -ExecutionPolicy Bypass -File scripts/export-typeless-dataset.ps1

npm 入口：

bash
npm run typeless:export

如果要通过 npm 传参数，需要多加一层 --：

bash
npm run typeless:export -- -- --limit 10 --no-audio

常用参数：

  • --typeless-dir <path>：指定 Typeless 数据目录，默认 Windows 为 %APPDATA%/Typeless.exe。
  • --db <path>：直接指定 typeless.db。
  • --out-dir <path>：指定导出目录。
  • --limit <n>：只导出前 n 条，用于冒烟测试。
  • --no-audio：不复制录音。
  • --redact-text：将文本字段替换成 hash 和长度。
  • --include-local-paths：包含原始绝对音频路径，默认关闭，避免泄漏用户名和本机目录。
  • --include-debug-info：包含 Typeless debug_info 原文，默认关闭。
  • --include-raw-db：复制 typeless.db，默认关闭。这个选项非常敏感，只适合明确授权的内部分析。

脚本只依赖 Python 标准库。它使用 SQLite backup API 读取数据库快照，不直接写 Typeless 原始目录。

导出产物 ​

每次导出会生成一个目录：

text
artifacts/datasets/typeless/typeless-export-<timestamp>/

目录内容：

  • typeless-dataset.xlsx：人工查看和筛选用 Excel。
  • records.csv：整理后的表格数据，UTF-8 BOM，方便 Excel/Sheets 打开。
  • records.jsonl：整理后的机器可读数据。
  • history_raw.jsonl：原始 history 行，BLOB 字段只记录 byte length 和 sha256。
  • manifest.json：导出配置、计数、源字段、时间范围。
  • README.md：包内隐私说明。
  • recordings/：复制出的 .ogg 录音文件。
  • typeless-dataset.zip：上述文件的完整打包。

Excel 工作表 ​

typeless-dataset.xlsx 包含：

  • Summary：导出时间、总行数、非空 refined_text 数、音频打包数、时间范围。
  • Records：每条历史记录的主数据。
  • Field Dictionary：字段来源、说明、隐私级别和评估用途。
  • App Distribution：按 focused_app_name 聚合。
  • Status Distribution：按 status 聚合。
  • Mode Distribution：按 mode 聚合。
  • Scene Distribution：按启发式场景聚合。
  • Dataset Use：按建议用途聚合。

关键字段 ​

主记录字段分四类。

身份与时间：

  • id：Typeless 记录 ID。
  • created_at / updated_at：记录时间。
  • status：如 transcript、dismissed、error。
  • mode：如 voice_transcript、voice_command、voice_translation。

文本与 teacher output：

  • refined_text：Typeless refined output，是 teacher/reference。
  • refined_text_length：用于过滤空输出、短句和长文本。
  • edited_text / edited_text_status：Typeless 若有用户编辑结果，则可作为人工纠正信号。

音频与技术元数据：

  • audio_file_name：原始 .ogg 文件名。
  • audio_package_path：导出包内相对音频路径。
  • audio_exists：音频是否存在。
  • audio_size_bytes：音频大小。
  • audio_sha256：音频 hash，用于去重和完整性校验。
  • audio_context_length / audio_context_sha256：Typeless opaque audio_context 的长度和 hash。当前不把它当可解释数据。
  • audio_codec、audio_format、audio_sample_rate、audio_channels、audio_bitrate、audio_duration_metadata：来自 audio_metadata。

上下文与评估辅助：

  • focused_app_name：录音时聚焦应用。
  • focused_app_window_title / focused_app_window_web_title / focused_app_window_web_domain / focused_app_window_web_url：可辅助判断场景，但隐私敏感。
  • candidate_scene：脚本启发式推断的初始场景，如 chat、email、notes、dev_handoff、general。
  • risk_tags：脚本启发式打的风险标签，如 number、url、negation、self_correction、mixed_en_cn、list_like。
  • dataset_use：建议用途，如 teacher_eval_candidate、audio_replay_without_teacher、failure_or_dismissed_review。

隐私边界 ​

默认导出包含真实 refined_text 和真实音频。这个包属于敏感个人数据，不能直接提交仓库，也不能在未授权情况下外发。

默认保护措施：

  • 不导出原始绝对 audio_local_path，避免泄漏本机用户名和目录。
  • 不导出 debug_info 原文。
  • 不复制 typeless.db。
  • BLOB 字段只记录 byte length 和 sha256。
  • 导出目录加入 .gitignore。

分享给协作者前应至少确认：

  • 是否有授权分享音频和文本。
  • 是否需要用 --redact-text 生成只含 hash 的结构包。
  • 是否要删除 window title、web URL、app/domain 等上下文。
  • 是否只分享脱敏后的 golden cases，而不是完整私有包。

与评估体系的关系 ​

完整评估系统分五层。

  1. 数据采集层

从 Typeless 导出 audio + refined_text + context + metadata。这一层只解决数据可得性，不判断 VILab 好坏。

  1. VILab 重放层

对 recordings/*.ogg 重新跑当前 VILab 链路，得到：

text
audio -> raw_transcript -> smart_clean -> polished

同时记录：

  • STT provider/model
  • transform provider/model
  • prompt version/source/hash
  • fallback reason
  • provider error
  • latency
  1. Teacher 对齐层

将 VILab polished 与 Typeless refined_text 对齐比较。这里不能做简单字符串相等，而要看意图、结构、自然度、专名、数字、否定句和可发送性。

  1. 自动评分层

规则评分负责硬约束：

  • 数字、日期、时间、URL、账号、专名不能丢。
  • 否定词不能反转。
  • 不能空输出。
  • 不能 prompt 泄漏。
  • 不能语言漂移。
  • 不能把 Codex/Cursor、VILab/Typeless 等专名误改。

LLM judge 负责软质量：

  • 意图保真。
  • 清理质量。
  • 结构化整理。
  • 可读性。
  • 人味保留。
  • 安全失败识别。
  1. 人工复核与 golden set 层

低分样本、争议样本和高价值场景进入人工复核。人工复核后脱敏，沉淀为 repo 内可提交的 golden cases。repo 里的 golden cases 不应包含真实音频、真实人名、真实公司、真实 URL 或完整隐私上下文。

采样策略 ​

第一轮建议先从 teacher_eval_candidate 中做 100 条分层样本：

  • 按 focused_app_name：Codex、Feishu、Chrome、Code、Weixin 等。
  • 按 candidate_scene：chat、notes、email、dev_handoff、general。
  • 按 duration_seconds：短句、中句、长口述。
  • 按 risk_tags：number、url、negation、self_correction、mixed_en_cn、list_like。
  • 按 refined_text_length：过滤过短文本，同时保留部分真实短句。

第二轮扩到 300 条，第三轮再考虑全量重放。

当前可执行评估流程 ​

  • 用 typeless:teacher-eval 从导出包里生成第一批 100 条分层样本和 replay-queue.jsonl：
bash
npm run typeless:teacher-eval

如果要通过 npm 传参：

bash
npm run typeless:teacher-eval -- -- --sample-size 100 --include-text
  • 将 replay-queue.jsonl 作为 VILab replay eval 的输入。
  • 用 typeless:replay 连接正在运行的 VILab HTTP 服务，生成 replay-results.jsonl：
powershell
$env:VILAB_REPLAY_API_KEY = "<external-api-key>"
$env:VILAB_LAB_TOKEN = "<prompt-lab-token>"
npm run typeless:replay -- -- --server-url http://127.0.0.1:9876

VILAB_REPLAY_API_KEY 用于 /v1/audio/transcriptions；VILAB_LAB_TOKEN 用于 /admin/lab/compare。脚本也支持 --api-key 和 --lab-token 显式传参，但默认建议用环境变量，避免密钥出现在命令历史里。如果只想验证音频转写，可加 --skip-lab-compare。

  • 用 typeless:replay-score 生成 VILab replay 后的 Typeless teacher 对齐报告：
bash
npm run typeless:replay-score -- -- --teacher-dir <typeless-teacher-dir> --replay-results <replay-results.jsonl>

报告对比同一条音频下的 Typeless refined 与 VILab raw/smart/polished，并标记低分样本和 golden case 候选。
