Lab 全链路 Case、评分维度与链路保存格式 ​

更新时间：2026-05-25

这份文档描述当前 Lab 测试平台中 Typeless 全链路 case 的保存格式、五个评分维度的计算方式，以及建议用于保存高价值链路配置的简化 JSON 格式。

1. 全链路 Case 保存格式 ​

当前全链路 case 只保留测试必需信息，不保存 scene、source、sha256 等派生或追踪字段。

json
{
  "id": "ba774536-226a-4792-93e6-5ac2a97b343b",
  "audioPath": "lab-full-chain-audio/ba774536-226a-4792-93e6-5ac2a97b343b.wav",
  "gold": "我想了解一下 VILab 这个项目的这几个方面：\n\n1. 项目进展\n2. 后续计划",
  "userProfiles": ["developer"],
  "focusedAppName": "Notepad.exe",
  "durationSeconds": 14.528,
  "createdAt": "2026-05-21T02:01:26.007Z",
  "riskTags": ["hotword_accuracy", "structure_required", "mixed_language"],
  "hotwords": ["VILab"]
}

字段说明：

字段类型说明
idstringcase 唯一 id。
audioPathstring音频文件路径，支持 lab-full-chain-audio/... 或 typeless-export-.../recordings/...。
goldstring期望输出文本，也是除热词外的基础评分标准。
userProfilesstring[]持久化用户画像列表，例如 developer、designer、biomedicine。测试时可选择是否输入上下文。
focusedAppNamestring录制时聚焦应用，例如 Notepad.exe、Codex.exe。
durationSecondsnumber音频时长。
createdAtstring创建时间，ISO 8601。
riskTagsstring[]评分标签，一个 case 可以对应多个标签。
hotwordsstring[]关键词列表，只用于关键词识别正确率评分。

当前允许的 riskTags：

json
[
  "hotword_accuracy",
  "structure_required",
  "filler_cleanup",
  "mixed_language",
  "self_correction"
]

2. 五维评分方式 ​

每个 variant 的总览中固定显示五个维度。没有对应 case 或无法计算时显示 -。

2.1 hotword_accuracy ​

热词维度不使用 Gold 距离，而使用命中率：

text
score = round(hitHotwords / totalHotwords * 100)

展示格式：

text
hotword_accuracy 33 (1/3)

含义：

  • 33：归一化到 0-100 的分数。
  • 1/3：命中 1 个热词，总共 3 个热词。
  • 如果总热词数为 0，则显示 -。

2.2 其他四个维度 ​

以下四类暂时统一使用输出文本和 Gold 的整体距离评分：

text
structure_required
filler_cleanup
mixed_language
self_correction

单条 case 的基础分：

text
score = max(0, round((1 - editDistance(tokens(gold), tokens(output)) / len(tokens(gold))) * 100))

token 规则：

  • 中文、日文、韩文字符按单字符切分。
  • 拉丁字母和数字按连续片段切分。
  • 标点符号作为非空白 token 参与比较。

边界情况：

  • Gold 为空且输出也为空：100
  • Gold 为空但输出非空：0
  • 最低分不低于 0

某个标签的 variant 总分：

text
tagScore = average(scoreAgainstGold(case.gold, variant.output))

只统计带有该标签的 case。没有 case 时显示 -。

3. 链路保存格式 ​

链路保存只保存 Lab 前端可设置的链路内容，以及该链路最近一次批测的五维得分。目标是简化、清晰、可选择、可复用。

不建议保存：

  • API Key 明文
  • 每条 case 的完整输出
  • System/User prompt trace
  • ASR 原文、diff、候选热词细节
  • 大量运行时调试字段

推荐单条链路 JSON：

json
{
  "schemaVersion": 1,
  "kind": "vilab.fullChainLink",
  "id": "full-chain-link-20260525-001",
  "title": "SenseVoice + Doubao baseline",
  "createdAt": "2026-05-25T10:30:00+08:00",
  "updatedAt": "2026-05-25T10:45:00+08:00",
  "config": {
    "variantTitle": "Baseline",
    "modelConfigId": "doubao-seed-1-6",
    "asrConfigId": "sensevoice-local",
    "providerId": "volcengine-ark",
    "apiFormat": "openai",
    "apiBaseUrl": "https://ark.cn-beijing.volces.com/api/v3",
    "model": "doubao-seed-1-6",
    "thinkingMode": "off",
    "proxyMode": "auto",
    "proxyUrl": "",
    "mode": "polished",
    "promptPresetId": "polish-chat-v1",
    "systemPromptOverride": "",
    "userPromptOverride": "{{sceneContext}}\n{{textContext}}\n{{hotwordContext}}\n原始转录（Raw transcript）：\n{{rawTranscript}}\n\n初步清洗稿（Smart clean draft）：\n{{smartCleanDraft}}",
    "sceneContextPrompt": "识别场景：{{scene}}\n置信度：{{confidence}}\n结构倾向：{{structureHint}}",
    "textContextPrompt": "当前文本框上下文：\n{{textContext}}",
    "hotwordContextPrompt": "运行时热词上下文。以下热词在当前输入中超过召回阈值。仅当输入内容明确支持时，才把它们作为 ASR 修复候选；请保留标准写法，不要凭空编造新名称：\n{{hotwords}}",
    "includeSceneContext": true,
    "includeTextContext": true,
    "includeHotwordContext": true,
    "hotwordContextMode": "threshold",
    "includeProfessionalContext": true,
    "includeUserProfileContext": true,
    "streamOutput": false
  },
  "scores": {
    "hotword_accuracy": {
      "score": 33,
      "hit": 1,
      "total": 3
    },
    "structure_required": 70,
    "filler_cleanup": null,
    "mixed_language": 75,
    "self_correction": null
  },
  "lastRun": {
    "caseCount": 9,
    "runCount": 9,
    "averageScore": 75,
    "failureCount": 0,
    "averageDurationMs": 3338,
    "totalDurationMs": 30040
  }
}

说明：

  • config 只保存 Lab 前端可以设置或选择的链路内容。
  • apiKey 默认不保存。链路复用时依赖本地模型配置或用户重新填写密钥。
  • scores 固定五个维度，缺失值使用 null，前端展示为 -。
  • hotword_accuracy 保存对象，因为需要同时展示 score 和 hit/total。
  • 其他维度保存 0-100 数字或 null。
  • lastRun 只保留总览指标，不保存逐条 case 细节。

4. 多条链路库格式 ​

如果本地用一个 JSON 文件保存多个高价值链路，推荐使用：

json
{
  "schemaVersion": 1,
  "kind": "vilab.fullChainLinkLibrary",
  "updatedAt": "2026-05-25T10:45:00+08:00",
  "links": [
    {
      "schemaVersion": 1,
      "kind": "vilab.fullChainLink",
      "id": "full-chain-link-20260525-001",
      "title": "SenseVoice + Doubao baseline",
      "createdAt": "2026-05-25T10:30:00+08:00",
      "updatedAt": "2026-05-25T10:45:00+08:00",
      "config": {},
      "scores": {
        "hotword_accuracy": { "score": 33, "hit": 1, "total": 3 },
        "structure_required": 70,
        "filler_cleanup": null,
        "mixed_language": 75,
        "self_correction": null
      },
      "lastRun": {
        "caseCount": 9,
        "runCount": 9,
        "averageScore": 75,
        "failureCount": 0,
        "averageDurationMs": 3338,
        "totalDurationMs": 30040
      }
    }
  ]
}

推荐本地路径：

text
<db_parent>/prompt_lab_full_chain_links.json

推荐接口：

text
GET /admin/lab/full-chain/links
PUT /admin/lab/full-chain/links

这样比单个快照文件更轻，适合在 Variant Workspace 中读取、选择、覆盖和复用高价值链路。
